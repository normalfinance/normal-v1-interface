The Asset Surfaces Audit

Branch chore/console-hygiene, 2026-08-28 — every surface that displays assets, checked for the hero-card failure class: a sticky loading flag blanking healthy data. Two more instances found and fixed.

1 · What the audit looked for

Doc 116 established the class: companionPositionLoading is deliberately sticky (its “still loading” test is data === undefined, so error-retry gaps never flash a wrong $0) — but any surface that gates rendering on it without a bound will blank forever when the companion lookup dies. So the sweep traced every consumer of that flag, plus every asset surface’s loading gate, error rendering, and empty state.

3 · The pattern, stated once

Rule for future surfaces
A loading flag that is deliberately sticky (holds through error retries so it never flashes wrong data) may gate a row, but any gate that couples it to OTHER data’s rendering must be capped. Aesthetic “paint together” coupling is worth seconds, never an infinite blank. Three surfaces now carry the same 8-second cap: landing hero, portfolio page, drawer.
