Silent Consoles

Branch chore/console-hygiene (2026-08-28) — no app output in any real user’s browser console, enforced by lint so it stays that way.

1 · What was exposed, concretely

Anyone pressing F12 on the production app could watch it narrate itself. The audit found 129 raw console.* calls in 58 files. The client-side ones printed, among other things:

whatexample source
Your balances, before/after every swapthe [balance-gate] diagnostics
Transaction hashes and swap routing[lifi-swap], the CCTP engine’s failure dumps
Raw error objects that can embed the keyed RPC / Horizon URLs every console.error(…, err) in a fetch-failure path — the Alchemy and Validation Cloud keys ride inside those URLs
Passkey/credential diagnostics[passkey], [webauthn-guard]

2 · The rule the sweep enforced

One sentence
Browser consoles are silent in production; server logs stay, because they go to Vercel, not to users. Client code logs through a dev-gated logger — every method is a no-op unless NODE_ENV === 'development' — so we keep full diagnostics on localhost and users get nothing.

File by file, all 129 sites, three buckets:

bucketcountaction
Client code (components, hooks, sections, lib used by the browser) ~50 call sites in 27 files → logger.*. Dev keeps every diagnostic (the QA docs that reference [balance-gate] console lines still work on localhost); production browsers get silence.
Server code (API routes, cron, relayer, aggregator, middleware) ~79 call sites Kept as real console — these are the Vercel operational logs ([cron] refused, [portfolio] eth source failed, the Horizon failover warning, fee-escrow RECEIVABLE alerts). Silencing them would blind production. Each line’s content was audited too — see §3.
Comments that merely mention console (JSDoc examples) 5Untouched — they are documentation, not output.

3 · One real leak found by the content audit

The MoneyGram deposit route logged the SEP-24 interactive URL on the server — and that URL carries a one-time authentication token in its query string. Vercel logs are team-visible, not public, but a credential does not belong in any log. It now logs the destination without the query string: where it went, never the token.

4 · Enforcement — why this cannot rot back

ESLint’s no-console is now an error across the app, with a narrow, documented exemption list: the API/server/services directories, the five server-only lib modules whose warnings must reach Vercel logs, tests, and the logger sink itself. Consequence: if anyone writes console.log in client code, the lint gate fails the build. The sweep is a state; the lint rule is what makes it permanent.

5 · A trap hit and fixed mid-run — worth remembering

The heavy-barrel trap, second encounter
The first sweep imported logger from the @normalfinance/utils barrel — which drags @stellar/stellar-sdk and ESM-only packages along. Three jest suites for small pure modules (passkey-stamper, wallet-kit-guard, webauthn-guard) immediately failed to even parse. The fix is a dependency-free local logger (src/utils/logger.ts, behaviorally identical), and the swap turned out to matter beyond this sweep: 49 files across the app had standalone barrel imports just for logging — all now use the light module, which also trims what the client bundle drags in. Same lesson as the network-cookie test in run 7: never import a barrel for one small thing.
