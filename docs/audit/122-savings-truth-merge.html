1 · The question and the evidence

The reconciliation (both sides reproduced to the cent against Dune) showed the $14,835 gap was NOT deposit–withdraw cycles — both counters count every leg of a cycle. It was two real defects:

Cause → effect (the missing withdrawals)
If an action reaches the vault without going through the app — an external wallet (they 403 on the log-transaction routes, a known regression), or a direct DeFindex interaction → the chain records it but vault_deposits gets no row → any table built from the DB alone under-counts → the “all-time volume” counter reads low and nobody can say why. DB rows: $38,000 of savings volume. Chain truth: $52,481.

2 · The fix — union, not replacement

Chain events carry no fee and no tx hash, and the revenue queries live off fee_usd — so blindly replacing DB rows with chain events would zero out recorded revenue. Instead activity_v2’s savings rows are now a truth-merge:

  • Every DB row survives as-is — it holds the fee we actually charged.
  • Every chain event (DeFindex events API, per wallet) that matches a DB row (same wallet + type, amount within max($0.02, 1%), time within 24h, one-to-one nearest-first) is absorbed — no double row.
  • Every chain event that matches nothing becomes a fee-0 row — real volume, but we never charged revenue on it, and inventing a fee would lie to the revenue queries.
