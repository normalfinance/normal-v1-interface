Safari Compatibility Audit

Branch chore/console-hygiene, 2026-08-28 — prompted by a coworker’s iPhone screenshot: coin assets not loading. A systematic sweep of every Safari hazard class in the client code, one confirmed bug fixed, everything else given a verdict.

1 · Why Safari specifically breaks things

Two facts combine badly. First, our build (Next/SWC with browserslist >0.5%, not dead) transpiles syntax for older browsers — but it never polyfills runtime APIs. A missing function on Safari simply throws at the moment it is called. Second, iPhones run whatever Safari their iOS ships — users on iOS 15 exist, and nothing we write in Chrome ever warns us.

2 · The confirmed bug — found and fixed

AbortSignal.timeout — Safari < 16.0
12 client-side call sites passed signal: AbortSignal.timeout(…) directly to fetch. On Safari older than 16.0 (Sep 2022) that static does not exist — the call throws a synchronous TypeError before the request is even sent. Affected paths, i.e. what silently dies on such a device: the Turnkey wallet lookup (wallet-info — the root of most balance surfaces), the gas reserve read, five CCTP status/autopilot calls, the MoneyGram client (3), the swap detail modal, and the refund flow. “Coin assets not loading” is exactly what the wallet-lookup failure looks like.

The fix: a dependency-free helper, utils/abort-timeout.ts — native AbortSignal.timeout when the platform has it, a timer-aborted AbortController when it doesn’t. Two tests, one of which deletes the platform API to prove the old failure mode (synchronous throw) is gone. All 12 client sites now use it; server-side files keep the native call (they run on Node, where it always exists).

4 · Watch items — real Safari quirks, no code change yet

itemwhy it matters on iOS
navigator.clipboard (10 sites) Safari only allows writes during a user gesture and can still reject. Our copy buttons are click-handlers (gesture ✓), but a rejection is silent on some. If a copy button “does nothing” on iPhone, this is where to look.
WebAuthn / passkeys (3 sites) Works on iOS Safari, but Apple is stricter about prompts that start long after the tap (our ceremonies sometimes follow quote/build fetches). If iPhone testing shows “operation not allowed” on signing, the fix is moving the prompt closer to the tap — noted, not preemptively rebuilt.
Safari ITP 7-day storage cap localStorage a user hasn’t touched for 7 days can be wiped — sessions and caches vanish, which looks like a random logout. Cosmetic-recoverable; worth knowing when a tester reports it.
iOS viewport (100vh, keyboard, safe-area) Purely visual; not audited in this pass.

5 · Honest limit + what to ask your coworker

I cannot run an iPhone from here
The fix in §2 is real and needed regardless — but whether it is your coworker’s bug depends on their iOS version. If they are on iOS 16+, something else is at play and I need two things from them:
  • iOS version — Settings → General → About → iOS Version.
  • The console — easiest: plug the iPhone into any Mac, Safari → Develop → their phone → the page, and screenshot the console. The first red line will name the culprit outright — this audit turns that line into a fix in minutes rather than another research round.
