Gas Float Monitoring

2026-09-02 — putting the relayer’s remaining gas on the Dune dashboard: why it matters more than it sounds, what the balances are today, and the exact plan. Run 127 (plan + live findings; no app code touched — a swap was in flight). Branch chore/console-hygiene.

Correction to this document’s first draft
The first version of this page called the empty Ethereum relayer urgent (“fund it first”). That was overstated, and the follow-up check proved it: the app’s CCTP pivot is hardcoded to Base (use-cctp-engine.tsx:857), and all 96 transfers ever recorded are base↔stellar — zero with an Ethereum destination. The Ethereum relayer account has never been funded or used (0 transactions, nonce 0). So nothing is broken and no user can reach that path today. It is a latent trap, not a live outage: the destChain === 'ethereum' branch exists in the state machine, so the day anyone enables an Ethereum destination, the first transfer would burn on the source chain and stall at the mint. Track it, guard it, do not panic about it.

Also corrected: an earlier check in this project looked at 0xC4d9…2aD5, the LI.FI fee wallet (revenue). The relayer is 0xc88a…7b43 — a different wallet entirely. Two wallets, two purposes; naming them loosely is what produced the false alarm.
What actually deserves attention
Stellar: 7.11 XLM. That account pays the mint fee for every inbound transfer (base→stellar — 50 of the 96 so far), and roughly 6 XLM is usable after the 1 XLM account reserve. At 0.05–0.5 XLM per mint that is ~12–120 more transfers: worth topping up to ~50 XLM soon, not an emergency. Base: 0.0107 ETH ($25.79) after 65 relayer transactions — healthy, and it is the wallet doing all the real work.

1 · What the relayer gas float is, and today’s numbers

Every CCTP transfer ends with our own relayer submitting the mint transaction on the destination chain, paying that chain’s gas from a hot wallet. One EVM key serves both Ethereum and Base; a separate Stellar account pays Soroban fees for Stellar-bound transfers.

How these were read (no key material printed or stored)
The addresses are derived from CCTP_RELAYER_EVM_PRIVATE_KEY and CCTP_RELAYER_STELLAR_SECRET in a local read-only script; only the public addresses and balances were output. The implementation below deliberately does not repeat that trick — see §2.

Why the float has barely moved
Base gas is fractions of a cent: 65 relayer transactions cost twelve cents in total. That is the whole reason a $20 float has survived three months of testing — and why the dashboard tile matters more for Stellar (XLM per mint is 100× the Base cost) than for Base.

2 · The plan (one pass, when no swap is in flight)

Least privilege: addresses, not secrets

The Dune sync must never import signing material. Two new public env vars carry the addresses instead — they are public information, safe in env and in logs:

CCTP_RELAYER_EVM_ADDRESS=0xc88a61BE2D640653978BC481A89D56c4A26a7b43
CCTP_RELAYER_STELLAR_ADDRESS=GDNDWW4ZHDSRRYSVO6XTFIX2UTMZGKPVNELZLZWY4SACLLJHGNZCUI5M

Both must also be declared in turbo.jsonc’s globalEnv — the env-audit test fails the build otherwise (it caught the LI.FI wallet vars the same way).

Rows

fetchGasFloat() in services/dune-sync-v2.ts reads the three balances (Ethereum + Base via the keyed RPCs, Stellar via the Horizon pool), each best-effort, and buildHoldingsRows appends one row per chain:

chain='treasury'  asset='GAS_ETHEREUM'  balance_total=<ETH>  usd_total=…
chain='treasury'  asset='GAS_BASE'      balance_total=<ETH>  usd_total=…
chain='treasury'  asset='GAS_STELLAR'   balance_total=<XLM>  usd_total=…

Per-chain, not one total — deliberately. Today’s aggregate reads “$27, fine” while Ethereum is at zero; a single number would have hidden exactly the problem this tile exists to catch.

The filter change that must land in the SAME run
The TVL queries currently exclude company money with asset != 'FEES'. Add gas rows without touching them and the relayer’s ETH silently inflates “user TVL”. So 3.11/3.12/3.13 switch to chain != 'treasury' — one condition that covers FEES, GAS and any future treasury bucket. (Run 15/16’s lesson: a new category must reach every classifier in the same run, not the next one.)

New dashboard queries

-- Gas float now, per chain (Bar — Y: asset, X: usd_total)
SELECT asset, SUM(balance_total) AS balance, SUM(usd_total) AS usd_total
FROM dune.normalfinance.normal_holdings_snapshots
WHERE chain = 'treasury' AND asset LIKE 'GAS%'
  AND snapshot_date = (SELECT MAX(snapshot_date)
                       FROM dune.normalfinance.normal_holdings_snapshots)
GROUP BY 1 ORDER BY 3 DESC;

-- Gas float over time (Line — X: day, Y: usd, one line per chain)
WITH ranked AS (
  SELECT date_trunc('day', CAST(snapshot_date AS timestamp)) AS day, asset, usd_total,
         row_number() OVER (PARTITION BY date_trunc('day', CAST(snapshot_date AS timestamp)),
                            asset ORDER BY snapshot_date DESC) AS rn
  FROM dune.normalfinance.normal_holdings_snapshots
  WHERE chain = 'treasury' AND asset LIKE 'GAS%'
)
SELECT day, asset, usd_total FROM ranked WHERE rn = 1 ORDER BY day;

The second one is the point of the whole exercise: the table is append-only, so after a few daily syncs the slope tells you the burn rate — how many days of gas remain — instead of just today’s number.

3 · Why this was not built during the swap

A BTC→USDC swap was in flight on the dev server. Editing anything under packages/web/src triggers a Next fast-refresh: funds are never at risk (the transfer is on-chain and the relayer runs server-side), but a remount can lose the client-side tracker that records the swap into swap_logs and drives the progress UI — leaving a completed swap missing from activity and from Dune. Docs live outside the module graph, so this file is safe to write. Implementation waits for a quiet moment.

4 · Ops note beyond the dashboard

A chart shows you the problem only when you look at it. Once the rows exist, a Dune alert on the gas-float query (Dune → the query → Alerts) can notify when any chain drops below a threshold — the real fix for “the relayer ran dry and nobody noticed”. Suggested thresholds: Ethereum < 0.01 ETH, Base < 0.002 ETH, Stellar < 20 XLM.
