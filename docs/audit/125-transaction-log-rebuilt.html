Transaction Log Rebuilt

2026-09-01 — the old normal_transaction_log only ever saw Soroswap swaps and savings, and its “fee_usd” column was not in dollars. It is now built from the same rows as activity_v2. Run 125, branch chore/console-hygiene.

1 · What was wrong

That table had its own builder (fetchTransactionLog in services/prisma-sync.ts) that read swap_logs and vault_deposits directly — written before CCTP, sends and ramps existed, and never revisited. Two defects:

defecteffect on your query
Only two source tablesCCTP swaps, sends and on/off-ramps were invisible. LI.FI swaps were present (they live in swap_logs) but indistinguishable — every swap said action_type = 'swap', which is why the table looked Soroswap-only.
fee_usd held raw token units (Number(feeAmount), unconverted)a 0.5 XLM fee was logged as “0.5” in a column named USD — the same class of bug doc 122 fixed in the volume table.
Root cause, worth naming
Two builders were producing overlapping tables from the same database. When new products shipped, only one of them was updated. This is the same failure mode as run 15/16 (a new status taught to the state machine but not to the banner’s classifier): duplicate sources of truth drift silently. The fix is not to patch the second builder — it is to delete it.

2 · The fix

filechange
src/lib/dune/transaction-log.ts (+5 tests)NEW pure mapper: buildTransactionLogRows(activityRows) projects the v2 rows into the legacy table’s fixed schema, and transactionActionType maps product+action to an action_type. Completed rows only — this table has always logged what happened, not what was attempted.
services/prisma-sync.tsfetchTransactionLog deleted. One table, one source.
api/cron/dune-sync/route.tsUploads both tables from a single fetchActivityV2() call — no second DeFindex fan-out, no extra seconds. If the activity fetch fails, the log step reports SKIPPED: activity fetch failed rather than vanishing from the response.

Backward compatibility (deliberate)

Existing dashboard widgets that filter this table keep working, because the old values keep their exact meaning:

swap             ← Soroswap swap        (unchanged)
savings_deposit  ← savings deposit      (unchanged)
savings_withdraw ← savings withdrawal   (unchanged)
swap_lifi        ← NEW: LI.FI cross-chain swap
swap_cctp        ← NEW: CCTP swap
send             ← NEW
onramp / offramp ← NEW (Coinbase, MoneyGram)
Labelled limitation
The Dune table’s columns are fixed at creation, so this projection is lossy on purpose: no product, status, chain or amount_usd column exists there. Recreating the table to add them would break every saved widget, so instead doc 119 §3.16 gives the richer query against normal_activity_v2 — use that for anything new.
