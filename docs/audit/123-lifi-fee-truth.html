Correction, added by doc 124
This document calls the fee wallets “LI.FI fees”. They are integrator fees, and the pot is shared: the CCTP flow’s 0.5% is itself a LI.FI integrator fee (api/cctp/quote/route.ts), so CCTP’s recorded $6.91 is inside that same balance. Doc 124 rewrites the revenue queries accordingly — attributing the whole wallet balance to LI.FI would have double-counted CCTP.

3 · Change B — fee wallets join the holdings snapshot (the TVL ask)

fetchHoldingsSnapshot now reads the fee wallets (ETH mainnet + Base via RPC, BTC via mempool, SOL when the env var exists — each best-effort) and appends ONE row: chain='treasury', asset='FEES', USD-valued, mirroring the SAVINGS row pattern. Combined-TVL (3.11/3.12) and holdings-now (3.13) pick it up automatically as its own bucket — and because it is its own bucket, any query can exclude company money from user holdings with WHERE asset != 'FEES'. turbo.jsonc declares the three LIFI_FEE_WALLET_* vars (the env-audit gate caught that).
